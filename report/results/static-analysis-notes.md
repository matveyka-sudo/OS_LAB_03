# Разбор дополнительного статического анализа Apple Clang

Команда: clang --analyze -std=c11 -Wall -Wextra -Wpedantic main.c -Xanalyzer -analyzer-output=text.
Исходный вывод: static-analysis.txt. Получено два предупреждения анализатора.

1. Строка 126, потенциально нулевой pthread_t при pthread_join.
Массив ids первоначально обнулён calloc. Анализатор не учитывает запись
действительного pthread_t функцией pthread_create при её успешном результате.
stop_pool получает число успешно созданных потоков; элемент с неудачным create
никогда не передаётся join. Для обычного завершения все actual-1 create успешны.
Это ложное срабатывание на модели внешнего вызова.

2. Строка 204, потенциально неинициализированный x[j].
В показанном пути анализатор одновременно предполагает n<=0 при входе в gauss,
пропускает все её циклы, а затем предполагает n>0 внутри verify. В действительном
управлении main размер допускается только от 1 до 10000, pool.n=n и далее n
не меняется. При успехе gauss обратный ход заполняет все x. При неуспехе verify
не вызывается. Это недостижимая комбинация предположений анализатора.

Код не менялся ради подавления предупреждений. Выполнены также 124 проверки
в Release, 124 с ASan+UBSan и 124 с TSan, плюс 3 CTest. Санитайзеры не дали диагностик.

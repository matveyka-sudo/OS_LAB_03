# Лабораторная работа №3. Операционные системы

Вариант 10: решение СЛАУ методом Гаусса с частичным выбором главного элемента.
C11, CMake, POSIX Threads. Исходный алгоритм целиком в `main.c`, математических
библиотек кроме стандартной `math.h` нет. Проект создан на macOS, Apple M1.

## Сборка и запуск

Откройте эту папку через File → Open в CLion и дождитесь загрузки CMake.
Для установленного CLion добавлен preset `apple-clang`: после загрузки
`CMakePresets.json` выберите профиль Apple Clang Release. Он явно указывает
`/usr/bin/clang`; существующие глобальные настройки IDE с GCC не изменялись.
Presets требуют CMake 3.21+, обычные команды ниже работают с CMake 3.16+.
В конфигурации запуска задайте аргументы, например `--size 1000 --threads 4`.
Рабочая папка для примеров с файлами должна быть корнем проекта.

В терминале из корня проекта (macOS или Ubuntu с установленными CMake и компилятором):

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_FLAGS_RELEASE='-O2 -DNDEBUG'
cmake --build build
./build/OS_Lab3_Variant10 --size 1000 --threads 4
./build/OS_Lab3_Variant10 --file tests/three.txt --threads 4
./build/OS_Lab3_Variant10 --help
```

`--size` и `--file` взаимоисключающие; один из них обязателен.
`--threads` обязателен и ограничивает **общее** число потоков вместе с main.
Фактически создаётся `min(P,N)` участников: main и ещё `min(P,N)-1` рабочих.
При P=1 вычисляет только main. Допустимы N=1..10000, P=1..256.
Предел N защищает размер выделения памяти; N=10000 требует около 1,6 ГБ
для двух расширенных матриц и очень большого времени O(N³).

## Входной файл

Первая строка: N. Далее N строк, в каждой N коэффициентов и свободный член.
Разделитель: пробельные символы. Десятичная точка: `.`. Пример `tests/three.txt`:

```text
3
2 1 -1 8
-3 -1 2 -11
-2 1 2 -3
```

Ответ: (2, 3, -1). NaN, infinity, недостаток или избыток чисел отклоняются.
Генератор использует фиксированное начальное состояние 10, диагональное
преобладание и эталон `x[j] = j % 7 - 3`, где j начинается с нуля.

## Как устроены потоки

Постоянный набор рабочих создаётся один раз. На шаге k основной поток выбирает
и переставляет ведущую строку. Рабочие получают номер шага через mutex и cond.
Каждый участник меняет свой непрерывный диапазон строк ниже k; ведущую строку
все только читают. Main считает свой диапазон, потом ждёт счётчик `done`.
Новый шаг начинается только после завершения всех диапазонов.
Обратная подстановка последовательная. В конце `stop_pool` будит рабочих,
они выходят, а main вызывает `pthread_join` и освобождает память.

Порог ведущего элемента: `DBL_EPSILON * N * max(abs(A[i,j]))`.
Он отсекает вырожденные и часть численно опасных систем, но не является
оценкой числа обусловленности. Программа не различает отсутствие решений
и бесконечное множество: в обоих случаях сообщает, что безопасное
единственное решение недоступно. Очень плохо масштабированная обратимая
матрица также может быть отклонена по этому консервативному порогу.

Проверка: `||Ax-b||inf / (||A||inf * ||x||inf + ||b||inf) <= 1e-10`;
для генератора дополнительно `max|x-x_ref| <= 1e-8`.
Коды возврата: 0 — успех/справка; 1 — ввод, память, pthread;
2 — вырожденная или численно опасная система; 3 — проверка решения не пройдена.
Невязка сама по себе не гарантирует малую ошибку x для плохо обусловленной системы.

## Проверки

```sh
ctest --test-dir build --output-on-failure
python3 tests/run_tests.py
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DCMAKE_C_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer'
cmake --build build-asan
python3 tests/run_tests.py build-asan/OS_Lab3_Variant10
cmake -S . -B build-tsan -DCMAKE_BUILD_TYPE=Debug -DCMAKE_C_FLAGS='-fsanitize=thread -fno-omit-frame-pointer'
cmake --build build-tsan
python3 tests/run_tests.py build-tsan/OS_Lab3_Variant10
```

Сценарии требуют только Python 3; они сравнивают известные ответы, проверяют
повороты, вырожденность, аргументы, масштаб 1e-100, нулевую правую часть,
размеры до 1000 и 25 повторов многопоточного решения. JSON-журналы находятся
в `report/results`. Успешный прогон не доказывает отсутствие любых возможных
ошибок; синхронизация также проверена по структуре доступа к данным.

## Наблюдение потоков

macOS, из корня проекта:

```sh
./build/OS_Lab3_Variant10 --size 1000 --threads 4 --demo 20 &
pid=$!
ps -M -p "$pid"
wait "$pid"
```

В выводе `ps -M` одна строка после заголовка соответствует одному потоку.
Пауза начинается после создания рабочих и до запуска таймера. Во время паузы
потоки спят; после паузы те же потоки действительно выполняют алгоритм.
Проверка 1/2/4/8 потоков и случая N<P: `python3 tests/check_threads.py` (macOS).
Настоящие снимки вывода `ps` сохранены как `report/results/threads-*.txt`.

Ubuntu: в том же примере замените только команду наблюдения на:

```sh
ps -T -p "$pid"
```

Ubuntu в этой сессии недоступна; эта команда и запуск программы там не проверялись.
Linux-специфичных вызовов в исходном алгоритме нет, `pthread_barrier_t` не используется.

## Измерения и отчёт

```sh
python3 tests/benchmark.py
python3 tests/plot_results.py
```

Для графиков нужны Python и matplotlib. Измерения делаются по одному процессу,
без параллельного запуска тестов: N=100/300/600/1000; P=1/2/4/8; один прогрев
и семь запусков, порядок конфигураций перемешан с фиксированным seed.
Таймер `CLOCK_MONOTONIC` охватывает всю `gauss`: выбор опоры, перестановки,
исключение, ожидания и обратный ход. Генерация, создание/завершение набора
потоков, демопауза, проверка и печать исключены. Это время решения с готовым
набором потоков, а не полное время процесса. `S=T1/Tp`, `E=S/p`, p включает main.
К концу прямого хода строк меньше p, поэтому часть участников не получает строк.

Исходные времена — `report/results/raw.csv`; медианы и формулы — `summary.csv`;
реальная среда и контрольная сумма C-кода — `environment.json`.
Графики PNG и итоговый PDF находятся в `report`. Редактируемый отчёт —
`report/latex/main.tex` и `src/*.tex`; полный исходник C включается автоматически.

Сборка отчёта установленным Tectonic:

```sh
cd report/latex
tectonic main.tex
cp main.pdf ../Лабораторная_работа_3_Вариант_10.pdf
```

Либо XeLaTeX: `xelatex main.tex` (пакеты из TeX Live).
Оформление адаптировано из [шаблона преподавателя](https://github.com/Yadroff/OS_report_template):
титульный лист, A4, поля 2,54 см, шрифт 12 pt, разделы и листинг.
Изменения стиля и лицензия указаны в `report/latex/TEMPLATE_NOTES.md`.
ФИО, группа и преподаватель оставлены для заполнения. Разбор всех функций,
циклов, вопросов и устный рассказ находятся в `ЗАЩИТА.md`.

Git-репозиторий локальный, удалённый адрес не настроен. Сборочные каталоги,
настройки IDE и временные файлы исключены из Git.
